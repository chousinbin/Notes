# PDF2zh-next 安装与使用手册

> 适用环境：macOS（Apple Silicon）、Homebrew 安装 `uv`、使用 `uv tool` 安装 PDFMathTranslate-next  
> 编写日期：2026-09-07  
> 项目主页：[PDFMathTranslate/PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next)

## 1. 软件简介

PDFMathTranslate-next（命令名为 `pdf2zh_next`）用于翻译 PDF 文档，并尽量保留原文中的公式、图表、目录、注释和版式。它提供命令行、WebUI 和 Docker 等使用方式。项目基于 BabelDOC，也是调用 BabelDOC 进行 PDF 翻译的官方参考实现。[1]

对于 macOS，项目文档推荐使用 `uv` 安装；WebUI 的正确启动参数是 `--gui`，不是 `web` 子命令。[1][3]

## 2. 本机安装结构说明

当前机器采用如下结构：

```text
Homebrew
└── uv 0.12.10
    └── uv tool 独立工具环境
        ├── Python 3.12
        ├── pdf2zh-next 2.9.0
        └── 命令：~/.local/bin/pdf2zh_next
```

这意味着：

- `uv` 本身由 Homebrew 安装，而不是由 `pip` 安装。
- PDFMathTranslate-next 由 `uv tool` 安装在一个独立环境中。
- 它当前使用 Python 3.12，不依赖 Homebrew 的系统级 Python 3.14。
- 不应直接进入该工具环境后使用 `pip` 修改依赖；`uv` 官方建议不要手动改变 `uv tool` 创建的隔离环境。[6]

可以用以下命令核对本机状态：

```bash
brew list --versions uv
uv --version
command -v uv
command -v pdf2zh_next
uv tool dir
uv tool dir --bin
```

本机的典型路径为：

```text
/opt/homebrew/bin/uv
~/.local/share/uv/tools/pdf2zh-next/
~/.local/bin/pdf2zh_next
```

`uv tool install` 会为每个命令行工具建立持久、隔离的虚拟环境，并把可执行文件链接到工具命令目录；默认工具环境通常位于 `~/.local/share/uv/tools`。[6][7]

## 3. 安装步骤

### 3.1 安装 Homebrew

如果电脑还没有 Homebrew，请按照其官网说明安装：

- [Homebrew 官方网站](https://brew.sh/)

安装后检查：

```bash
brew --version
```

### 3.2 使用 Homebrew 安装 uv

```bash
brew install uv
```

检查版本：

```bash
uv --version
```

`uv` 官方文档确认其位于 Homebrew Core 中，可直接通过 `brew install uv` 安装。[5]

由于这里是由 Homebrew 管理 `uv`，升级时应使用：

```bash
brew update
brew upgrade uv
```

不要使用：

```bash
uv self update
```

`uv self update` 主要用于官方独立安装器版本；通过包管理器安装时，应继续使用对应包管理器升级。[5]

### 3.3 使用 uv 安装 PDFMathTranslate-next

PDFMathTranslate-next 官方要求兼容的 Python 版本，并在 macOS 的 `uv` 安装说明中给出 Python 3.12 的安装方式。[2]

执行：

```bash
uv tool install --python 3.12 pdf2zh-next
```

这里的含义是：

- `uv tool install`：将 Python 命令行应用作为独立工具安装。
- `--python 3.12`：为它选择 Python 3.12。
- `pdf2zh-next`：PyPI 包名。
- `pdf2zh_next`：安装后实际使用的终端命令名。

如果本机没有 Python 3.12，`uv` 可以自动获取兼容版本；也可以提前执行：[8]

```bash
uv python install 3.12
```

### 3.4 修复 `command not found`

如果出现：

```text
zsh: command not found: pdf2zh_next
```

优先让 `uv` 自动更新 shell 配置：

```bash
uv tool update-shell
```

关闭终端并重新打开，然后检查：

```bash
command -v pdf2zh_next
```

也可以手动把 `~/.local/bin` 加入 `PATH`：

```bash
echo 'export PATH="$PATH:$HOME/.local/bin"' >> ~/.zshrc
source ~/.zshrc
```

PDFMathTranslate-next 和 `uv` 的官方文档均指出，工具命令目录必须位于 `PATH` 中。[2][6]

## 4. 启动 WebUI

命令是：

```bash
pdf2zh_next --gui
```

服务成功启动后，浏览器通常会自动打开。如果没有自动打开，请访问：

- [http://localhost:7860/](http://localhost:7860/)

这是项目官方 WebUI 文档指定的默认地址。[3]

关闭终端窗口也会停止本地服务。

## 5. WebUI 使用方法

1. 执行 `pdf2zh_next --gui`。
2. 打开 `http://localhost:7860/`。
3. 把 PDF 拖入上传区域，或点击选择文件。
4. 确认源语言和目标语言。
5. 选择翻译引擎，并根据需要填写 API Key、模型名或服务地址。
6. 点击 `Translate`。
7. 等待解析、翻译、排版和输出。
8. 下载单语版或双语版 PDF。

官方 WebUI 文档同样采用“上传 PDF—点击 Translate”的工作流。[3]

WebUI 的默认语言方向还可以通过环境变量设置：

```bash
export PDF2ZH_LANG_FROM="English"
export PDF2ZH_LANG_TO="Simplified Chinese"
pdf2zh_next --gui
```

这两个变量分别对应源语言和目标语言。[3]

## 6. 命令行使用方法

### 6.1 最简单的翻译

进入 PDF 所在目录：

```bash
cd ~/Desktop
pdf2zh_next document.pdf
```

如果文件名或路径包含空格，必须加引号：

```bash
pdf2zh_next "My Paper.pdf"
```

官方命令行文档说明，输出默认生成在当前工作目录中；可用 `pwd` 查看当前目录。[4]

### 6.2 指定语言和输出目录

英文翻译为简体中文：

```bash
pdf2zh_next document.pdf \
  --lang-in en \
  --lang-out zh \
  --output ./translated
```

中文翻译为英文：

```bash
pdf2zh_next document.pdf \
  --lang-in zh \
  --lang-out en \
  --output ./translated
```

语言代码请参考项目的[语言代码文档](https://pdf2zh-next.com/advanced/Language-Codes.html)。

### 6.3 翻译指定页码

```bash
pdf2zh_next document.pdf --pages "1-10"
```

或者：

```bash
pdf2zh_next document.pdf --pages "1,3,5-8"
```

### 6.4 查看全部可用参数

不同版本可能增加、删除或调整参数，因此高级用法应首先查看本机版本的帮助：

```bash
pdf2zh_next --help
```

也可参考官方的[高级用法](https://pdf2zh-next.com/advanced/advanced.html)。

## 7. 维护、升级和卸载

### 7.1 查看已安装工具

```bash
uv tool list
```

### 7.2 升级 PDFMathTranslate-next

```bash
uv tool upgrade pdf2zh-next
```

`uv` 官方说明，`uv tool upgrade` 会升级对应工具环境，同时保留安装时使用的版本约束和相关设置。[6]

升级后检查：

```bash
pdf2zh_next --version
```

### 7.3 重新安装

```bash
uv tool install --python 3.12 --reinstall pdf2zh-next
```

如果现有工具环境损坏，也可以先卸载后安装：

```bash
uv tool uninstall pdf2zh-next
uv tool install --python 3.12 pdf2zh-next
```

### 7.4 卸载

```bash
uv tool uninstall pdf2zh-next
```

这会删除 `uv tool` 为软件创建的隔离环境。翻译缓存和配置目录可能仍然保留，不会自动全部删除。

### 7.5 升级 uv

由于本机的 `uv` 来自 Homebrew，应使用：

```bash
brew update
brew upgrade uv
```

## 8. 常见问题排查

### 8.1 `command not found: pdf2zh_next`

```bash
uv tool update-shell
exec zsh
command -v pdf2zh_next
```

如果仍不存在：

```bash
uv tool install --python 3.12 --reinstall pdf2zh-next
```

### 8.2 `Downloading all assets...` 后长时间没有输出

先查看缓存：

```bash
du -sh ~/.cache/babeldoc
```

再测试主要下载站点能否访问：

```bash
curl -I https://huggingface.co/
curl -I https://www.modelscope.cn/
curl -I https://raw.githubusercontent.com/
```

如果连接失败，检查代理、DNS、防火墙或当前网络。不要随意使用 `--allow-insecure-host` 绕过 TLS 校验。

### 8.3 缓存目录权限错误

典型报错：

```text
PermissionError: Operation not permitted: ~/.cache/pdf2zh_next
```

先检查目录：

```bash
ls -ld ~/.cache ~/.cache/pdf2zh_next ~/.cache/babeldoc
```

确保目录存在且当前用户可读写：

```bash
mkdir -p ~/.cache/pdf2zh_next ~/.cache/babeldoc
chmod u+rwx ~/.cache/pdf2zh_next ~/.cache/babeldoc
```

如果是在受限或沙箱化的内置终端中运行，目录即使属于当前用户，也可能被宿主程序限制。此时应改用 macOS 自带的 Terminal 或 iTerm2 运行。

### 8.4 7860 端口已经被占用

查看占用者：

```bash
lsof -nP -iTCP:7860 -sTCP:LISTEN
```

改用其他端口：

```bash
pdf2zh_next --gui --server-port 7861
```

### 8.5 系统 Python 是 3.14，会不会冲突

通常不会。本机的 PDFMathTranslate-next 是通过：

```bash
uv tool install --python 3.12 pdf2zh-next
```

安装的，因此它在自己的工具环境中使用 Python 3.12。`uv tool` 的设计目的之一就是隔离工具依赖，避免与系统 Python 或当前项目环境相互污染。[6]

不要用以下命令判断该工具是否安装：

```bash
python3 -m pip show pdf2zh-next
```

这条命令查询的是当前 `python3` 对应的 `pip` 环境，并不一定是 `uv tool` 的独立环境。应改用：

```bash
uv tool list
command -v pdf2zh_next
pdf2zh_next --version
```

## 9. uv 与 Conda 的区别

### 9.1 核心定位

`uv` 是以 Python 工作流为中心的高速包和项目管理工具，覆盖 Python 版本管理、虚拟环境、依赖解析、锁文件、项目运行，以及类似 `pipx` 的命令行工具安装。[5][6][8]

Conda 是跨语言的软件包、依赖和环境管理器。Conda 环境比 Python `venv` 更底层：Python 本身可以作为环境内的依赖，并且 Conda 能管理 R、Perl、系统库和任意可执行程序等非 Python 依赖。[9][10]

### 9.2 对比表

| 维度 | uv | Conda |
|---|---|---|
| 主要生态 | Python、PyPI、Python 项目工具链 | Conda channels，多语言和二进制软件栈 |
| 核心用途 | Python 依赖、虚拟环境、锁文件、Python 版本、CLI 工具 | 环境管理、Python/R 等语言、原生库和二进制依赖 |
| 环境形式 | 常见为 `.venv`；`uv tool` 为每个 CLI 应用建独立环境 | 命名或路径环境，需要 `conda activate` 切换 |
| Python 管理 | 能发现、下载和选择 Python | Python 本身就是 Conda 环境中的一个包 |
| 非 Python 依赖 | 主要依靠 wheel 内置库或系统包管理器，如 Homebrew | 可直接把系统级库、R、Perl、可执行程序作为 Conda 包管理 |
| 包来源 | 主要是 PyPI 和 Python package indexes | defaults、conda-forge 或其他 Conda channels，也可在环境中使用 pip |
| 锁定与项目复现 | `uv.lock`、`pyproject.toml`、`uv sync` | `environment.yml`、显式锁文件、环境导出 |
| CLI 工具安装 | `uv tool install`，类似 pipx，工具之间隔离 | 通常为工具创建独立 Conda 环境并激活或用 `conda run` |
| 启动和解析体验 | 通常更轻量、快速 | 环境功能更广，复杂科学依赖解析可能更重 |
| 典型优势 | 纯 Python 项目、CLI 应用、快速安装与锁定 | CUDA、GDAL、FFmpeg、R、C/C++ 库等复杂二进制科研环境 |

### 9.3 什么时候选 uv

适合使用 `uv` 的情况：

- 软件主要来自 PyPI；
- 需要快速创建 Python 项目环境；
- 希望使用 `pyproject.toml` 和锁文件；
- 需要安装独立的 Python 命令行应用；
- 不希望每次使用工具前手动激活环境。

PDFMathTranslate-next 正属于最后两种情况。使用：

```bash
uv tool install --python 3.12 pdf2zh-next
```

后，直接执行 `pdf2zh_next --gui` 即可。因此在当前场景下，`uv tool` 比专门创建并激活 Conda 环境更直接。

### 9.4 什么时候选 Conda

适合使用 Conda 的情况：

- 项目同时依赖 Python 和大量非 Python 原生库；
- 需要在同一个环境管理 R、Perl、CUDA 工具或系统级二进制依赖；
- 科学计算软件明确提供 Conda/conda-forge 安装方案；
- 需要控制底层二进制兼容性。

Conda 官方文档指出，Conda 环境可以管理系统级库、非 Python 依赖并显式跟踪二进制依赖。[9]

### 9.5 uv 和 Conda 能否共存

可以共存，但建议明确边界：

- 全局 Python CLI 工具：优先使用 `uv tool install`。
- 纯 Python 项目：优先使用 `uv init`、`uv add`、`uv sync`。
- 复杂科学计算或跨语言环境：使用 Conda/Miniforge。
- 不要同时让 `uv` 和 Conda 无规则地修改同一个环境。

如果必须在 Conda 环境中安装 PyPI 包，可以先让 Conda 管理 Python 和原生库，再在已激活环境中谨慎使用项目指定的 Python 包工具；要避免两个解析器交替升级同一批依赖。

## 10. 推荐的日常命令

```bash
# 启动 WebUI
pdf2zh_next --gui

# 翻译单个文件
pdf2zh_next "paper.pdf"

# 查看版本
pdf2zh_next --version

# 查看帮助
pdf2zh_next --help

# 查看 uv 管理的工具
uv tool list

# 升级 PDFMathTranslate-next
uv tool upgrade pdf2zh-next

# 升级 Homebrew 版 uv
brew update
brew upgrade uv

# 查看首次启动资源缓存
du -sh ~/.cache/babeldoc
```
